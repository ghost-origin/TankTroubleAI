# 地图生成与可视化 —— 矩阵 → CSV → 画图 全链路说明

本文档解释坦克动荡 3 的地图（迷宫）从**游戏设计数据**到**画在图上**的每一步转换。
所有数值都已与运行时实际数据核对过，可放心作为参考。

---

## 一、总览：五层结构

```
① mazes.json（设计数据，1001 张迷宫）
        │  每局随机选一张（控制台打印 "Found maze #N"）
        ▼
② 运行时瓦片图（Tilemap 对象 type 38，内存中的 30×20 网格）
        │  ai-bridge.js 读 getTileAt()，原始 tile 值（含方向标志）
        ▼
③ 桥发送的 map 字段（WebSocket JSON）
        │  record_ws.py 取左上角 10×10 写 CSV
        ▼
④ maze_*.csv（固定 10 行 10 列，每格 = 原始 tile 值）
        │  plot_tracks.py 解码 + tile_polys.json 画墙线
        ▼
⑤ 轨迹图 PNG（真实迷宫墙线 + 双方坦克轨迹）
```

关键概念就一句话：**迷宫数据是"墙块摆放图"，墙是格内的 3px 细线，不是整格挡死**。
每格一个墙块 id（1~5），墙块只在格内画几段细线，**格子剩余部分就是通道**。

---

## 二、第①层：设计数据 `assets/mazes.json`

文件内容：1001 张迷宫（键 `"0"` ~ `"1000"`），每张是**一个 JSON 字符串**（c2array 格式），
解开来是：

```json
{
  "c2array": true,
  "size": [10, 10, 2],              ← 10行 × 10列 × 每格2个值
  "data": [                          ← 10 行，每行 10 格
    [[2, 90],  [5, 0],  [3, 90], ...],   ← 每格 = [墙块id, 旋转角度]
    [[3, 180], [1, 0],  [5, 90], ...],
    ...
  ]
}
```

### 每格两个值的含义

| 值 | 含义 |
|---|---|
| `[0, 0]` | 路格（无墙线）—— 整格空旷 |
| `[1~5, 0~270]` | 墙块：1=直墙段、2=拐角、3=T形、4=十字、5=直墙变体 |
| 第二个值 | 旋转角度：0 / 90 / 180 / 270（度） |

迷宫里**几乎没有 0 格**（100 格中往往 0~3 个）—— 因为路不需要用 0 格表示，
**通道是墙块细线之间的空白**。

---

## 三、第②层：运行时瓦片图（游戏内存）

对局开始，游戏从 1001 张里**随机选一张**（控制台日志 `Found maze #83` 之类），
把它的 10×10 **写入瓦片图对象（type 38，Tilemap 插件）的左上角 10×10 区域**。

瓦片图对象的参数（固定）：

| 参数 | 值 |
|---|---|
| 实例位置 (x, y) | (197.5, 31) —— 世界坐标下的迷宫左上角 |
| 格宽 / 格高 | 57 × 57 像素 |
| 画布 mapwidth × mapheight | 30 × 20 格（只有左上 10×10 是迷宫，其余 -1 空白） |

### 写入值 = tile_id + 方向标志（位编码）

运行时把 `[tile_id, rotation]` 合成**一个整数**再写入：

```
写入值 = tile_id (低29位)  |  方向标志 (高3位)
```

| 方向标志 | bit 值 | 含义 |
|---|---|---|
| `H` 水平翻转 | 0x80000000 | 左右镜像 |
| `V` 垂直翻转 | 0x40000000 | 上下镜像 |
| `D` 对角翻转 | 0x20000000 | 主对角线镜像 |

**旋转角度 → 标志位**（与构造器 StateComboToFlags 完全一致，已实测核对）：

| 旋转角度 | 标志组合 | 例（tile 2） |
|---|---|---|
| 0°    | 无 | `2` |
| 90°   | H + D | `0xA0000002` = **-1610612734**（有符号） |
| 180°  | H + V | `0xC0000002` = -1073741822 |
| 270°  | V + D | `0x60000002` = 1610612738 |

> 桥 / CSV 里保存的就是这个**带符号整数**。负数出现是因为最高位（H 标志）被当作符号位。

### 读格子：`tilemapInstance.getTileAt(col, row)`

```
-1          = 画布空白（迷宫外的 20×10 区域）
0           = 路格（格子内无墙线）
±tile_id    = 该格有墙块（带方向标志）
```

## 四、第③层：桥发送的 map 字段（WebSocket）

`ai-bridge.js` 每 3 秒（布局变化时立即）读取瓦片图并发送给 Python 端：

```json
{
  "w": 30, "h": 20,           // 画布尺寸（格）
  "tileW": 57, "tileH": 57,   // 格像素
  "x": 197.5, "y": 31,        // 迷宫左上角世界坐标
  "ox": 0, "oy": 0,           // 瓦片图偏移
  "grid": [ [原始tile值, ...], ... ],   // 30 行 × 20 列，左上 10×10 是迷宫
  "polys": [ ... ]             // 可选：15 个墙块多边形（归一化 0~1）
}
```

## 五、第④层：CSV 记录 `maze_<时间戳>.csv` → `track_<时间戳>.csv`

`record_ws.py` 收到 map 字段后，**只取左上角 10×10** 写入迷宫 CSV：

```
maze_20260901_085921.csv    ← 10 行 × 10 列，每格 = 原始 tile 值（含方向标志）
```

真实样子（某局前两行）：

```
-1610612734,-1610612731,-1073741821,-1610612731,...
5,-1073741823,-1610612735,1610612739,...
```

解码后：

```
tile2HD, tile5HD, tile5HD, tile3HV, ...
tile5直,  tile1HV, tile1HD, tile3VD, ...
```

**与 mazes.json 的对应关系**（第①层 → 第④层，一局实际数据的验证）：

| mazes.json 格 `[id, 旋转]` | 解码后的 CSV 值 |
|---|---|
| `[2, 90]` | `tile2HD`（2 + 90°=H+D） |
| `[5, 0]` | `tile5直`（5 + 无标志） |
| `[3, 90]` | `tile3HV`（3 + 90°=H+D）… |

## 六、第⑤层：画图 `plot_tracks.py`（矩阵 → 像素 → 墙线）

输入：`track_时间戳.csv`（轨迹）+ 同名 `maze_时间戳.csv`（迷宫）+ `tile_polys.json`（墙块形状）。

### 6.1 墙块多边形库 `tile_polys.json`

从游戏数据 `data.js.base` type38 提出来（15 个 tile id 的多边形，**归一化 0~1 坐标**）：

| tile | 格内形状（57px 格，单位 px） |
|---|---|
| 0 | 中心 3×3 小方块 (27,27)-(30,30) |
| 1 | 半高竖线 (27,0)-(30,30) |
| 2 | 拐角 L 形 |
| 3 | T 形 |
| 4 | 十字/复杂形 |
| 5 | 全高竖线 (27,0)-(30,57) |
| 9~14 | 边框/边线（用于画布边缘） |

### 6.2 单格转换步骤（核心算法）

对迷宫里每格 `(cx, cy)`、`tile 值 v`，画墙线分四步：

```
① 解码 tile 值
   uv = v & 0xFFFFFFFF
   tid = uv & 0x1FFFFFFF        ← 墙块 id
   flips: H = uv & 0x80000000
          V = uv & 0x40000000
          D = uv & 0x20000000

② 取多边形并放大到格内像素
   pts = [(x*57, y*57) for (x,y) in tile_polys[tid]]

③ 应用翻转（顺序与 C2 引擎 cacheTilePoly 一致）
   先 D：交换 x,y → (y, x)
   再 H：x → 57 - x
   再 V：y → 57 - y

④ 平移到格子位置 + 画线
   世界坐标 = (格x*57 + px, 格y*57 + py)
   连接多边形顶点成环 → 就是 3px 细墙线
```

> 注意：**旋转不是旋转 90°**，而是**对角翻转 + 镜像**的组合（C2 引擎的等价实现）。
> 因为墙块都是细线，对角+水平镜像 ≈ 旋转 90°，这是引擎的优化，结果与旋转完全一致。

### 6.3 坐标系与方向

- 地图坐标系：**左上角 (197.5, 31) 为原点**，x 向右，y **向下**为正
- 轨迹数据 `track_*.csv` 里 me/foe 坐标已经是"世界坐标 - (197.5, 31)"即地图坐标系
- 画图时 `ax.invert_yaxis()` 反转 y 轴 —— 因为游戏 y 向下、matplotlib 默认 y 向上，不反转会上下颠倒

### 6.4 输出效果

```
迷宫墙线（深色细线）   ← 来自 maze_*.csv + tile_polys.json
    ├─ 网格线（浅灰）
    ├─ 我方轨迹（蓝色）  ← me_*
    ├─ 敌方轨迹（红色）  ← foe_*
    └─ 起终点标记（圆圈/方块）
```

## 七、常见问题（都已踩过坑）

| 现象 | 原因 |
|---|---|
| 迷宫画成一整片灰方块，无通道 | ❌ 错误做法：把 `tile_id>0` 的整格涂灰。墙是格内细线，应画 3px 线留通道 |
| 轨迹上下颠倒 | matplotlib y 轴向上，游戏 y 向下，需要 `invert_yaxis()` |
| CSV 里全是负数 | 这是 `tile_id | 0x80000000(H标志)` 的有符号表示，高位是负号，属正常 |
| CSV 里几乎没 0 | 路不靠 0 格表示，通道是墙块细线之间的空白，100 格里通常 0~3 个 0 |
| 旋转方向不对 | 旋转= D→H→V 顺序的组合变换，与 C2 `cacheTilePoly` 保持一致即可 |
